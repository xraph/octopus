# FARP & discovery

FARP (the Forge API Gateway Registration Protocol) provides service discovery and automatic
routing. The `farp` section is optional and disabled by default. For conceptual depth, see the
[FARP](/docs/farp) section.

```yaml
farp:
  enabled: true
  watch_interval: 5s
  schema_cache_ttl: 5m
  discovery:
    backends:
      - type: kubernetes
        enabled: true
        config:
          namespace: default
          label_selector: "app.kubernetes.io/part-of=myapp"
          watch_interval: 10s
```

## `farp`

| Key | Type | Default | Description |
| --- | --- | --- | --- |
| `enabled` | boolean | `false` | Enable FARP service discovery and auto-routing. |
| `watch_interval` | duration | `5s` | Interval for discovering service changes. |
| `schema_cache_ttl` | duration | `5m` | Schema cache time-to-live. |
| `discovery` | object | none | Discovery backend configuration. See [below](#discovery). |
| `registration_token` | string | none | Token callers must present to register, update or remove services. See [Registration token](#registration-token). |
| `gateway` | object | none | Bind FARP routes to hostnames and a virtual gateway. See [Gateway binding](#gateway-binding). |

## Registration token

With `registration_token` set, every FARP request whose method is not `GET` or `HEAD` needs the
token, on all of the `/_farp/v1`, `/__farp`, `/__/farp` and `/farp` prefixes. Send it as
`Authorization: Bearer <token>` or as `X-Octopus-Farp-Token: <token>`. A request without it gets
a `401` with `WWW-Authenticate: Bearer realm="octopus-farp"`. Reads stay open.

```yaml
farp:
  enabled: true
  registration_token: "${OCTOPUS_FARP_TOKEN}"
```

Read the token from the environment rather than writing it into the file. A `${VAR}` that is not
set fails the config load, so a missing secret stops the gateway instead of leaving registration
open. The token is held as a SHA-256 digest, never serialized into config output, and never
logged. An empty string counts as no token.

If FARP is enabled with no token, the gateway starts and logs a warning. See the
[FARP registration API](/docs/api/farp#authentication) for the exact request and response shapes,
including what a service should do when a heartbeat comes back `404` after a gateway restart.

## Gateway binding

`farp.gateway` puts every FARP route on the hostnames you list, and on no other host.

```yaml
farp:
  enabled: true
  gateway:
    hostnames: ["api.acme.dev", "*.acme.dev"]
    gateway_id: platform-api
    default_auth_provider: jwt
```

| Key | Type | Default | Description |
| --- | --- | --- | --- |
| `hostnames` | array of string | `[]` | Hostnames every FARP route lands on: exact hosts (`api.acme.dev`) or `*.zone` wildcards. Wins over `hostname` when both are set. |
| `hostname` | string | none | Legacy single hostname. Still read, and used only when `hostnames` is empty. Checked leniently, see below. |
| `gateway_id` | string | none | Virtual gateway id attached to each FARP route. |
| `default_auth_provider` | string | none | Auth provider for FARP routes whose service doesn't declare one. |
| `default_rate_limit_per_minute` | integer | none | Rate limit applied to FARP routes. |
| `default_timeout` | duration | none | Per-request timeout applied to FARP routes. |

Entries in `hostnames` follow the same rules as [route hosts](/docs/configuration/routes):
lowercase ASCII labels, with `*.` allowed only as the first label. With FARP enabled, config
loading fails on anything else and the error names the entry, for example
`farp.gateway.hostnames[1]`. A wildcard never covers its apex, so `*.acme.dev` matches
`api.acme.dev` but not `acme.dev`; list both if you want both.

The legacy `hostname` loads the way it always has. `""` and `"*"` mean any host. A value the
strict rules reject, such as `my_svc.local`, still loads: the gateway logs a warning and matches
it as written. Move to `hostnames` when you want the check.

With no hostnames at all (none listed, or a legacy `hostname` of `""` or `"*"`), FARP routes
match any host and still pick up `gateway_id`, the auth provider, the rate limit and the
timeout. While `farp.enabled` is `false` the hostnames aren't checked.

Each service gets one route per method and per hostname. The shape is the same whether the
service registered itself over the push API or a discovery backend found it. For a service named
`billing` that declares `GET /invoices`, the gateway adds:

- path `/billing/invoices` (the service name lowercased, then the declared path),
- `strip_prefix: /billing`, so the service receives `/invoices`,
- priority `100`,
- upstream `billing`, named after the FARP `service_name`.

All of a service's routes share the route id `farp:<service_name>` and report origin `farp` in
the [admin API](/docs/observability/admin-api#routes-crud). When the service registers again, the
gateway replaces that whole set, so a route the service stopped declaring goes away. When it
deregisters, or discovery stops seeing it, the gateway removes its routes and its upstream.

A route you declare yourself, in `routes[]` or through the admin API, wins over a FARP route on
the same method, host and path, whatever their priorities. FARP never removes it, and a
re-registration doesn't bring the FARP route back in front of it. Delete your route and the FARP
route serves that path again.

You can change the hostnames at runtime with
[`PUT /admin/api/farp/binding`](/docs/observability/admin-api#farp). That change is in memory
only. Write the same list into `farp.gateway.hostnames` too, or a restart puts the old one back.

## Discovery

`farp.discovery` holds a list of discovery backends.

| Key | Type | Default | Description |
| --- | --- | --- | --- |
| `backends` | array | `[]` | Discovery backends. Each is tagged by `type`. |

Each backend entry has a `type` (`mdns`, `dns`, `consul`, or `kubernetes`), an `enabled` flag
(default `true`), and a backend-specific `config` object.

<Tabs items={['mDNS', 'DNS', 'Consul', 'Kubernetes']}>

<div title="mDNS">

```yaml
- type: mdns
  enabled: true
  config:
    service_type: _http._tcp
    domain: local.
    watch_interval: 10s
    query_timeout: 2s
    enable_ipv6: true
```

`type: mdns`: mDNS/Bonjour discovery.

| Key | Type | Default | Description |
| --- | --- | --- | --- |
| `service_type` | string | none | Service type to discover. **Required.** |
| `domain` | string | none | mDNS domain. **Required.** |
| `watch_interval` | duration | none | Watch interval. **Required.** |
| `query_timeout` | duration | none | Query timeout. **Required.** |
| `enable_ipv6` | boolean | `true` | Enable IPv6 discovery. |

</div>

<div title="DNS">

```yaml
- type: dns
  enabled: true
  config:
    servers: ["10.0.0.53:53"]
    domain: services.internal
    watch_interval: 30s
```

`type: dns`: DNS-based discovery.

| Key | Type | Default | Description |
| --- | --- | --- | --- |
| `servers` | array of string | none | DNS server addresses. **Required.** |
| `domain` | string | none | Domain to query. **Required.** |
| `watch_interval` | duration | none | Watch interval. **Required.** |

</div>

<div title="Consul">

```yaml
- type: consul
  enabled: true
  config:
    address: http://consul:8500
    datacenter: dc1
    token: "${CONSUL_TOKEN}"
    watch_interval: 10s
```

`type: consul`: Consul discovery.

| Key | Type | Default | Description |
| --- | --- | --- | --- |
| `address` | string | none | Consul address. **Required.** |
| `datacenter` | string | none | Datacenter. **Required.** |
| `token` | string | none | ACL token. |
| `watch_interval` | duration | none | Watch interval. **Required.** |

</div>

<div title="Kubernetes">

```yaml
- type: kubernetes
  enabled: true
  config:
    namespace: default
    label_selector: "app.kubernetes.io/part-of=myapp"
    watch_interval: 10s
    use_endpoint_slices: true
    include_not_ready: false
```

`type: kubernetes`: Kubernetes discovery.

| Key | Type | Default | Description |
| --- | --- | --- | --- |
| `namespace` | string | none | Namespace to watch. **Required.** |
| `label_selector` | string | none | Label selector for filtering. |
| `watch_interval` | duration | none | Watch interval. **Required.** |
| `use_endpoint_slices` | boolean | `true` | Prefer the `discovery.k8s.io/v1` EndpointSlice API (falls back to Endpoints if unavailable). |
| `include_not_ready` | boolean | `false` | Include endpoints whose `ready` condition is false/unknown. |

</div>

</Tabs>

<Callout type="info">
  The `farp.discovery.kubernetes` backend is independent of the in-process Gateway API controller
  configured under [`kubernetes`](/docs/configuration/kubernetes). See [Kubernetes](/docs/kubernetes)
  for how the two relate.
</Callout>
