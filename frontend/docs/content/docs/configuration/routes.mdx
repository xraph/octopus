# Routes

A route maps an incoming request to an upstream. The `routes` field is an array; it defaults to
empty. Each route must reference an upstream that exists in [`upstreams`](/docs/configuration/upstreams)
(validation fails otherwise), and its `path` must start with `/`.

```yaml
routes:
  - id: users-api
    path: /api/users
    methods: [GET, POST]
    hosts: [api.example.com]
    upstream: user-service
    priority: 10
    strip_prefix: /api
    timeout: 15s
    auth_provider: primary-jwt
    require_roles: [admin]
    rate_limit:
      requests_per_window: 100
      window_size: 1m
    cors:
      allowed_origins: ["https://app.example.com"]
      allow_credentials: true
```

## `routes[]`

| Key | Type | Default | Description |
| --- | --- | --- | --- |
| `id` | string | none | Stable name for the route. Must be unique across `routes`. See [Route ids](#route-ids). |
| `path` | string | — | Path pattern to match. **Required** (must start with `/`). |
| `methods` | array of string | `[]` | HTTP methods to match. Empty means all methods: `GET`, `HEAD`, `POST`, `PUT`, `PATCH`, `DELETE` and `OPTIONS`. |
| `hosts` | array of string | `[]` | Request hosts to match, exact (`api.example.com`) or wildcard (`*.example.com`). Empty means any host. See [Host matching](#host-matching). |
| `upstream` | string | — | Target upstream name. **Required** (must exist in `upstreams`). |
| `priority` | integer | `0` | Higher priority routes are matched first. |
| `strip_prefix` | string | none | Prefix removed from the path before proxying. |
| `add_prefix` | string | none | Prefix prepended to the path before proxying. |
| `metadata` | map of string→string | `{}` | Arbitrary route metadata. |
| `auth_provider` | string | none | Auth provider name for this route (overrides the global `auth.default_provider`). |
| `skip_auth` | boolean | `false` | Skip authentication for this route. |
| `require_roles` | array of string | `[]` | Roles required for authorization. |
| `require_scopes` | array of string | `[]` | Scopes required for authorization. |
| `authz_rule` | string | none | Custom authorization rule (a Rhai expression). |
| `timeout` | duration | none | Per-route request timeout, overriding `gateway.request_timeout`. |
| `rate_limit` | object | none | Per-route rate limit. See [below](#rate-limit). |
| `cors` | object | none | Per-route CORS override. See [below](#cors). |

<Callout type="info">
  Routes have no `retry` or `canary` fields. Authentication and authorization behavior set here is
  evaluated by the auth middleware — see [Authentication & authorization](/docs/configuration/auth)
  and the [Security](/docs/security) section for the request flow.
</Callout>

## Host matching

`hosts` scopes a route to the request host: the HTTP/2 `:authority`, or the `Host` header on
HTTP/1.1. Leave it empty (or leave it out) and the route answers any host, which is how routes
behaved before `hosts` existed.

```yaml
routes:
  - path: /billing/*
    hosts: [api.acme.dev, "*.acme.dev"]
    upstream: billing
```

Each entry is one of two shapes:

- An exact host such as `api.acme.dev`. It matches that host and nothing else.
- A wildcard such as `*.acme.dev`. It matches any subdomain, at any depth (`eu.acme.dev`,
  `a.b.acme.dev`), but **never the apex**. `*.acme.dev` does not match `acme.dev`; list `acme.dev`
  as well if you want both.

A host pattern is a DNS name or an IPv4 address (`10.0.0.5`). IPv6 literals can't be written in
`hosts`, so a request that reaches the gateway at `[::1]` only matches routes with an empty `hosts`
list. `*` is only allowed as the first label (`api.*.dev` is rejected), and a bare `*` is rejected
too: an empty list already means any host. Patterns are trimmed and lowercased and lose one trailing
dot, so `API.Acme.Dev.` is the same as `api.acme.dev`.

The request host goes through the same normalization before it is compared. The port is dropped,
the value is lowercased and one trailing dot is removed, so `Host: API.Acme.Dev.:8443` matches a
route for `api.acme.dev`.

When several routes match a request, the one with the most specific host wins (exact, then
wildcard, then any host), and `priority` only breaks ties between routes whose hosts are equally
specific.

A route with several `methods` and several `hosts` is loaded as one route per method and host. All
of those copies share the route's `id`.

<Callout type="warn">
  A trailing `/*` in `path` needs at least one more segment. `/billing/*` matches `/billing/x`
  and `/billing/x/y`, but **not** `/billing` itself. Add a separate `/billing` route when the bare
  prefix has to be served.
</Callout>

### Declared routes and FARP routes

Routes from this file (and routes added through the admin API) are declared routes. Routes that
[FARP](/docs/concepts/farp) or the Kubernetes operator discover are not. When a declared route and
a discovered route have the same path and the same host pattern, the declared route wins whatever
their priorities are, and the discovered route stays hidden for as long as the declared one exists.

## Route ids

`id` gives a route a stable name. Every method and host copy of the route carries it, so tooling
can find, replace or remove the whole route by that one name. Ids are optional; when two routes set
the same `id`, validation fails with `duplicate route id`.

When several config files are [merged](/docs/configuration#loading-and-merging), a route with an
`id` overrides the earlier route with the same `id`. A route without one overrides the earlier route
with the same `path` and the same `hosts`.

## Rate limit

<Callout type="info">
  Per-route `rate_limit` and `cors` are **enforced**. `rate_limit` applies a fixed window per route
  (keyed by the route's path), returning `429` with `Retry-After` when exceeded — note it currently
  uses an in-process counter (per replica; a shared backend for cross-replica limits is planned).
  `cors` applies the matched route's override when a top-level [`cors`](/docs/configuration/auth)
  block is set (which adds the CORS middleware to the chain). See [Middleware](/docs/middleware).
</Callout>

The per-route `rate_limit` object uses a fixed window: a number of requests allowed per window
duration.

```yaml
rate_limit:
  requests_per_window: 100
  window_size: 1m
```

| Key | Type | Default | Description |
| --- | --- | --- | --- |
| `requests_per_window` | integer | — | Requests allowed per window. **Required.** |
| `window_size` | duration | — | Window length. **Required.** |

<Callout type="warn">
  This is the real schema. Older example files use `rate_limit: { requests_per_second: ... }`,
  which is **not** a valid field and is silently ignored.
</Callout>

## CORS

The per-route `cors` object overrides the global [`cors`](/docs/configuration/auth) policy for this
route.

```yaml
cors:
  allowed_origins: ["https://app.example.com"]
  allowed_methods: [GET, POST]
  allowed_headers: [Authorization, Content-Type]
  allow_credentials: true
  max_age: 3600
```

| Key | Type | Default | Description |
| --- | --- | --- | --- |
| `allowed_origins` | array of string | `[]` | Permitted origins. |
| `allowed_methods` | array of string | `[]` | Permitted HTTP methods. |
| `allowed_headers` | array of string | `[]` | Permitted request headers. |
| `allow_credentials` | boolean | `false` | Allow credentials (cookies, auth headers). |
| `max_age` | integer (seconds) | `3600` | Preflight cache max age. |

See [Routing](/docs/concepts/routing) for how path matching and priority resolve to a single route.
